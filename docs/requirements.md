# 要件定義書

スマートフォンWebアプリ：AR斬撃体験

⸻

1. 目的・背景

1.1 目的

スマートフォンの 実機センサー（加速度・カメラ） を活用し、
ユーザーが 現実世界を斬る体験 を提供する Web アプリケーションを開発する。

1.2 背景
	•	タッチ操作中心のWeb体験との差別化
	•	スマートフォン実機での検証価値を高める
	•	ネイティブアプリに近い没入感をWebで実現

⸻

2. 想定利用環境

項目	内容
デバイス	スマートフォン（iOS / Android）
ブラウザ	Safari（iOS）, Chrome（Android）
実行環境	HTTPS必須
画面向き	縦持ち（Portrait）


⸻

3. ユーザー体験（UX）

3.1 体験フロー
	1.	アプリ起動
	2.	カメラ使用許可
	3.	加速度センサー使用許可
	4.	カメラ映像が全画面表示される
	5.	ユーザーがスマホを振る
	6.	振った方向に斬撃エフェクトが発生
	7.	現実世界を斬ったような演出を体感

⸻

4. 機能要件

4.1 カメラ表示機能
	•	スマートフォンのカメラ映像をリアルタイムで表示する
	•	インカメラ／アウトカメラは初期実装ではアウトカメラを使用
	•	映像は画面全体に表示する

技術要件
	•	getUserMedia API を使用
	•	<video> 要素で描画
	•	playsinline を指定（iOS対策）

⸻

4.2 加速度検知機能
	•	端末の加速度変化を常時取得する
	•	一定以上の瞬間的な加速度変化を「斬撃」と判定する

判定条件
	•	前回加速度との差分の合成値が閾値を超えた場合
	•	閾値は実測により調整可能とする

⸻

4.3 斬撃方向判定
	•	加速度変化の方向から斬撃の方向を算出する
	•	左右・上下・斜め斬りに対応する

技術要件
	•	dx, dy を元に atan2 で角度算出

⸻

4.4 斬撃エフェクト描画
	•	斬撃はカメラ映像上に重ねて表示する
	•	Canvasを用いて描画する
	•	斬撃は一瞬表示され、フェードアウトする

表現仕様（初期）
	•	白色または青白い斬撃線
	•	画面中央を基準に全画面を貫く線
	•	太さと透明度を持つ

⸻

4.5 演出強化（任意）

以下は初期実装後に追加可能とする

演出	内容
発光	shadowBlur を用いた光表現
残像	フェードアウト処理
画面揺れ	軽微なCanvasシェイク
効果音	斬撃SEの再生


⸻

5. 非機能要件

5.1 パフォーマンス
	•	通常時は再描画を行わない
	•	斬撃発生時のみCanvas描画を行う
	•	フレーム落ちが体感されないこと

5.2 操作性
	•	タッチ操作を必須としない
	•	片手操作で完結すること

⸻

6. UI / レイヤー構成

6.1 表示レイヤー構成

[ Canvas（斬撃エフェクト） ]  最前面
[ Video（カメラ映像） ]       背景

6.2 レイアウト
	•	全画面表示
	•	UI要素（ボタン等）は最小限
	•	初回のみ「振って斬る」ガイド表示

⸻

7. セキュリティ・権限管理

7.1 権限取得
	•	カメラ使用許可
	•	加速度センサー使用許可（iOSは明示的リクエスト）

7.2 通信
	•	HTTPSのみ対応
	•	外部通信は行わない（ローカル処理のみ）

⸻

8. 制約・注意事項
	•	iOS Safariではセンサー使用にユーザー操作が必要
	•	ブラウザ・端末により加速度感度が異なる
	•	実測を前提としたチューニングが必要

⸻

9. 拡張予定（スコープ外）
	•	連続斬りコンボ
	•	ハンドトラッキングによる刀操作
	•	斬撃によるオブジェクト破壊演出
	•	WebXR対応

⸻

10. 成功条件
	•	ユーザーが 「現実を斬った」と直感的に理解できる
	•	操作説明なしでも振ることで体験できる
	•	実機での挙動が安定している
